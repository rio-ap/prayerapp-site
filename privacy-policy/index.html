Kebijakan Privasi

Terakhir diperbarui: 22 November 2026
Aplikasi: Prayer Alarm (com.trazire.prayerapp), versi 1.0
Pengembang: Trazire Gamedev Team

1. Ringkasan

Prayer Alarm adalah aplikasi pengingat waktu shalat. Aplikasi ini:

  • tidak membuat akun dan tidak meminta login;
  • tidak menampilkan iklan;
  • tidak memakai analitik, pelacak, atau pelaporan crash pihak ketiga;
  • tidak menjual atau menyewakan data Anda kepada siapa pun;
  • menyimpan jadwal, pengaturan, dan lokasi pilihan Anda di perangkat Anda sendiri.

Data hanya meninggalkan perangkat dalam tiga keadaan: (a) meminta jadwal shalat ke sumber jadwal (Kemenag, dan sebagai cadangan Aladhan), (b) layanan lokasi sistem operasi yang menyediakan posisi perangkat saat Anda meminta deteksi, dan (c) layanan geocoding sistem operasi, yang menerjemahkan koordinat menjadi nama kota dan menerjemahkan nama kota yang Anda pilih menjadi koordinat — yang terakhir ini juga terjadi bila Anda tidak pernah memberi izin lokasi (lihat bagian 4c).

2. Data yang diproses

3. Izin dan pilihan Anda

  • Lokasi (ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION) diminta lewat dialog sistem hanya ketika Anda memilih deteksi otomatis (Beranda) atau "Perbarui Lokasi" (Jadwal). Menolak izin ini tidak mematikan aplikasi: Anda dapat memilih provinsi dan kota/kabupaten secara manual, dan dalam jalur manual itu tidak ada posisi perangkat yang dibaca. Yang tetap terjadi hanyalah nama kota yang Anda pilih dikirim ke layanan geocoding sistem untuk diterjemahkan menjadi koordinat (bagian 4c); tanpa hasil geocoding, aplikasi memakai titik pusat ibu kota provinsi yang sudah ada di dalam aplikasi.
  • Notifikasi (POST_NOTIFICATIONS) dipakai untuk menampilkan alarm dan pengingat waktu shalat. Penolakannya terlihat jelas di dalam aplikasi.
  • Alarm presisi (SCHEDULE_EXACT_ALARM) dipakai agar alarm berbunyi tepat waktu. Tanpa izin ini alarm tetap berbunyi, tetapi dapat terlambat hingga 10 menit; aplikasi menjelaskan hal ini sebelum membuka layar pengaturan sistem.
  • INTERNET, ACCESS_NETWORK_STATE, RECEIVE_BOOT_COMPLETED, VIBRATE, WAKE_LOCK dipakai untuk mengambil jadwal, memulihkan alarm setelah perangkat dinyalakan ulang, bergetar, dan membunyikan alarm saat layar mati. Tidak satu pun dari izin ini mengumpulkan data pribadi.

4. Ke mana data dikirim

Kami tidak mengoperasikan server. Data hanya dikirim ke pihak berikut, dan hanya seperti yang dijelaskan di bawah.

a. Kementerian Agama RI — Bimas Islam (bimasislam.kemenag.go.id). Sumber utama jadwal shalat. Saat meminta jadwal bulanan, aplikasi mengirim ID provinsi, ID kota/kabupaten, bulan, dan tahun. Aplikasi tidak mengirim koordinat GPS ke Kemenag. Nama kota yang Anda pilih (atau yang terdeteksi dari GPS) dicocokkan di dalam perangkat dengan daftar kota Kemenag; yang dikirim ke server hanya ID wilayah.

b. Layanan Aladhan (api.aladhan.com) — hanya sebagai cadangan. Jika jadwal Kemenag gagal diambil (misalnya server tidak dapat dihubungi), aplikasi meminta jadwal ke Aladhan dan mengirim garis lintang, garis bujur, bulan, tahun, dan metode perhitungan. Ini satu-satunya layanan di luar platform perangkat yang menerima koordinat (layanan lokasi dan geocoding platform dibahas di (c)). Jika Kemenag berhasil, Aladhan tidak dihubungi sama sekali. Bila kedua sumber gagal, aplikasi menghitung jadwal di dalam perangkat tanpa mengirim koordinat ke mana pun.

c. Layanan lokasi dan geocoding sistem operasi (Android, termasuk Google Play services). Aplikasi memakai dua API platform, dan keduanya dapat ditangani oleh penyedia layanan perangkat (pada perangkat bersertifikasi Google: Google) sebagai bagian dari sistem operasi.

  • Penyedia lokasi. Posisi perangkat diambil lewat Fused Location Provider dari Google Play services — bukan dihitung sendiri oleh aplikasi. Panggilan ini hanya terjadi setelah Anda meminta deteksi (Beranda) atau "Perbarui Lokasi" (Jadwal) dan memberi izin lokasi; tanpa izin, panggilan itu tidak pernah dibuat.
  • Geocoding dua arah. API Geocoder milik Android dipakai untuk (i) menerjemahkan koordinat menjadi nama kota setelah deteksi, dan (ii) menerjemahkan nama kota yang Anda pilih menjadi koordinat saat Anda memilih kota secara manual — permintaan ini diulang setiap kali layar jadwal memuat kota tersebut, bukan hanya sekali saat kota dipilih. Permintaan (ii) berisi teks seperti "Kota Bandung, Jawa Barat, Indonesia" dan tetap dikirim meskipun Anda tidak pernah memberi izin lokasi — teks itu adalah nama tempat, bukan posisi perangkat. Tanpa hasil dari layanan ini, aplikasi memakai titik pusat ibu kota provinsi yang tersimpan di dalam aplikasi.

Aplikasi tidak menyimpan hasil geocoding di server mana pun dan tidak mengirimkannya ke pihak lain selain sebagai koordinat pada permintaan jadwal ke (a)/(b) di atas. Kami tidak mengendalikan kebijakan penyedia layanan platform tersebut; permintaan ini tunduk pada kebijakan privasi sistem operasi perangkat Anda.

d. Tidak ada pihak lain. Selain sumber jadwal di (a) dan (b) serta layanan platform di (c), tidak ada penerima data: tidak ada jaringan iklan, broker data, atau penyedia analitik yang menerima data dari aplikasi ini.

Seperti setiap permintaan web, server tujuan di atas dapat mencatat alamat IP dan waktu permintaan sebagai bagian dari log operasional mereka. Aplikasi tidak mengirim pengenal pengguna, akun, atau ID perangkat apa pun bersama permintaan tersebut. Semua koneksi memakai HTTPS; aplikasi menolak lalu lintas HTTP biasa (cleartext).

5. Yang tidak kami lakukan

  • Tidak ada akun, pendaftaran, atau profil pengguna.
  • Tidak ada iklan dan tidak ada pembagian data untuk iklan atau pemasaran.
  • Tidak ada analitik pemakaian, tidak ada pelaporan crash, tidak ada SDK Firebase.
  • Tidak ada penjualan, penyewaan, atau pertukaran data pribadi.
  • Tidak ada akses ke kontak, foto, berkas, mikrofon, kamera, atau lokasi latar belakang.

Aplikasi tidak meminta lokasi di latar belakang. Posisi perangkat hanya dibaca saat Anda menekan "Deteksi Lokasi Otomatis" di Beranda atau "Perbarui Lokasi" di layar Jadwal, yaitu saat aplikasi sedang terbuka di layar itu; setelah tersimpan, alarm dan arah kiblat memakai posisi tersebut tanpa membaca GPS lagi.

6. Penyimpanan dan penghapusan

Semua data tersimpan di penyimpanan internal aplikasi pada perangkat Anda (tidak dapat dibaca aplikasi lain di perangkat yang tidak di-root), dan tidak disertakan dalam pencadangan cloud Android — aplikasi menetapkan android:allowBackup="false".

Anda dapat menghapus semuanya kapan saja:

  • hapus data aplikasi lewat Setelan → Aplikasi → Prayer Alarm → Penyimpanan → Hapus data; atau
  • hapus pemasangan aplikasi.

Setelah itu tidak ada salinan data yang tersisa di perangkat. Karena kami tidak memiliki server atau akun pengguna, tidak ada data di sisi kami yang perlu dihapus.

7. Keamanan

Semua komunikasi jaringan memakai HTTPS dengan sertifikat sistem, dan konfigurasi keamanan jaringan aplikasi memblokir lalu lintas cleartext. Cookie sesi Kemenag hanya hidup di memori selama aplikasi berjalan dan tidak pernah ditulis ke disk.

8. Anak-anak

Aplikasi ini adalah utilitas umum untuk pengguna dewasa dan remaja; aplikasi tidak ditujukan kepada anak-anak, dan tidak mengumpulkan data pribadi apa pun dari siapa pun, termasuk anak-anak. Aplikasi tidak memiliki iklan, pembelian, atau konten yang dibuat pengguna, sehingga tidak ada jalur bagi anak untuk membagikan informasi.

9. Hak Anda

Karena aplikasi tidak memiliki akun dan tidak menyimpan data di server kami, kendali penuh ada di perangkat Anda: Anda dapat melihat data apa yang tersimpan (jadwal, kota, pengaturan), menghapusnya (bagian 6), dan menolak atau mencabut izin lokasi serta notifikasi kapan saja lewat Setelan Android. Mencabut izin lokasi tidak menghapus kota yang sudah tersimpan; pilih kota lain atau hapus data aplikasi untuk menggantinya.

10. Perubahan kebijakan

Jika kebijakan ini berubah, tanggal "Terakhir diperbarui" di atas akan diubah dan versi baru dipublikasikan di URL yang sama. Perubahan yang memengaruhi cara data diproses akan dijelaskan di catatan rilis aplikasi.

Privacy Policy

Last updated: 22 November 2026
App: Prayer Alarm (com.trazire.prayerapp), version 1.0
Developer: Trazire Gamedev Team

1. Summary

Prayer Alarm is a prayer-time reminder app. It:

  • does not create accounts and does not ask you to sign in;
  • does not show ads;
  • does not use analytics, trackers, or third-party crash reporting;
  • does not sell or rent your data to anyone;
  • stores your schedule, settings, and chosen location on your own device.

Data leaves the device in only three cases: (a) requesting prayer times from a schedule source (Kemenag, with Aladhan as a fallback), (b) the operating system's location service providing the device position when you ask for detection, and (c) the operating system's geocoding service, which turns coordinates into a city name and turns the city name you pick into coordinates — the latter also happens if you never grant location permission (see section 4c).

2. Data processed

The app does not ask for your name, email address, phone number, contacts, photos, files, microphone, camera, browsing history, or health data. It does not read the advertising ID (AD_ID) and ships no advertising SDK.

3. Permissions and your choices

  • Location (ACCESS_COARSE_LOCATION, ACCESS_FINE_LOCATION) is requested through the system dialog only when you choose automatic detection (Home) or "Perbarui Lokasi" (Schedule). Declining does not break the app: you can pick a province and city/regency manually, and on that manual path no device position is read. The only thing that still happens is that the city name you pick is sent to the system geocoding service to be turned into coordinates (section 4c); without a geocoding result the app uses the province capital's centre point, stored inside the app.
  • Notifications (POST_NOTIFICATIONS) are used to show prayer alarms and reminders. A denial is clearly visible inside the app.
  • Exact alarms (SCHEDULE_EXACT_ALARM) are used so the alarm rings on time. Without this permission the alarm still rings, but may be up to 10 minutes late; the app explains this before opening the system settings screen.
  • INTERNET, ACCESS_NETWORK_STATE, RECEIVE_BOOT_COMPLETED, VIBRATE, WAKE_LOCK are used to fetch the schedule, restore alarms after a reboot, vibrate, and ring the alarm while the screen is off. None of these permissions collects personal data.

4. Where data is sent

We do not operate a server. Data is sent only to the parties below, and only as described.

a. Ministry of Religious Affairs of the Republic of Indonesia — Bimas Islam (bimasislam.kemenag.go.id). The primary prayer-time source. When requesting a monthly schedule, the app sends the province ID, city/regency ID, month, and year. The app does not send GPS coordinates to Kemenag. The city name you pick (or that is detected from GPS) is matched on the device against Kemenag's city list; only the region ID is sent to the server.

b. Aladhan service (api.aladhan.com) — fallback only. If the Kemenag schedule cannot be fetched (for example, the server is unreachable), the app requests the schedule from Aladhan and sends the latitude, longitude, month, year, and calculation method. This is the only service outside the device platform that receives coordinates (the platform location and geocoding services are covered in (c)). If Kemenag succeeds, Aladhan is not contacted at all. If both sources fail, the app computes the schedule on the device without sending coordinates anywhere.

c. Operating-system location and geocoding services (Android, including Google Play services). The app uses two platform APIs, and both may be handled by the device's service provider (Google on certified devices) as part of the operating system.

  • Location provider. The device position is obtained through the Fused Location Provider from Google Play services — it is not computed by the app itself. This call happens only after you request detection (Home) or "Perbarui Lokasi" (Schedule) and grant location permission; without permission the call is never made.
  • Two-way geocoding. Android's Geocoder API is used to (i) turn coordinates into a city name after detection, and (ii) turn the city name you pick into coordinates when you choose a city manually — this request is repeated every time the schedule screen loads that city, not only once when the city is chosen. Request (ii) contains text such as "Kota Bandung, Jawa Barat, Indonesia" and is still sent even if you never granted location permission — it is a place name, not a device position. Without a result from this service the app uses the province capital's centre point stored inside the app.

The app does not store geocoding results on any server and does not send them to anyone other than as coordinates in the schedule requests to (a)/(b) above. We do not control the policies of those platform service providers; those requests are subject to the privacy policy of your device's operating system.

d. No one else. Besides the schedule sources in (a) and (b) and the platform services in (c), there are no data recipients: no advertising network, data broker, or analytics provider receives data from this app.

Like any web request, the destination servers above may log the IP address and time of the request as part of their operational logs. The app does not send any user identifier, account, or device ID with those requests. All connections use HTTPS; the app rejects plain HTTP (cleartext) traffic.

5. What we do not do

  • No accounts, registration, or user profiles.
  • No ads and no data sharing for advertising or marketing.
  • No usage analytics, no crash reporting, no Firebase SDK.
  • No sale, rental, or exchange of personal data.
  • No access to contacts, photos, files, microphone, camera, or background location.

The app does not request background location. The device position is read only when you tap "Deteksi Lokasi Otomatis" on Home or "Perbarui Lokasi" on the Schedule screen — that is, while the app is open on that screen; once stored, alarms and the qibla direction use that position without reading GPS again.

6. Storage and deletion

All data is stored in the app's internal storage on your device (not readable by other apps on a non-rooted device), and is not included in Android cloud backup — the app sets android:allowBackup="false".

You can delete everything at any time:

  • clear the app's data via Settings → Apps → Prayer Alarm → Storage → Clear data; or
  • uninstall the app.

After that no copy of the data remains on the device. Because we have no server or user accounts, there is no data on our side to delete.

7. Security

All network communication uses HTTPS with system certificates, and the app's network security configuration blocks cleartext traffic. Kemenag session cookies live in memory only while the app is running and are never written to disk.

8. Children

This app is a general utility for adult and teenage users; it is not directed at children, and it does not collect any personal data from anyone, including children. The app has no ads, purchases, or user-generated content, so there is no path for a child to share information.

9. Your rights

Because the app has no accounts and stores no data on our servers, full control stays on your device: you can see what data is stored (schedule, city, settings), delete it (section 6), and refuse or revoke location and notification permissions at any time through Android Settings. Revoking location permission does not delete a saved city; pick another city or clear the app's data to replace it.

10. Changes to this policy

If this policy changes, the "Last updated" date above will change and the new version will be published at the same URL. Changes that affect how data is processed will be described in the app's release notes.
